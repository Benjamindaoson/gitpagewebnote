# 笔记发布、知识网络与读者增长设计

## 目标

在不引入后端、数据库或私密令牌的前提下，增强现有 VitePress + GitHub Pages 笔记站的发布体验、知识关联、内容运营和读者反馈能力。

## 范围与约束

- Markdown 与 frontmatter 是唯一内容源；本地图片仍由导入器复制和重写链接。
- 站点保持可静态部署；不保存 GitHub Token、访问者身份或邮箱。
- GoatCounter 与 Giscus 均为可选的公开前端配置。未配置时，不加载第三方脚本，且构建不失败。
- 草稿不得出现在站点导航、搜索索引、RSS、Sitemap、推荐、双链或课程页中。
- 所有可由构建阶段确定的内容错误必须在 `npm run content:check` 中失败。

## 方案选择

采用“增强现有静态工作流”而不是网页后台或更换框架。

1. 本地 CLI 继续掌握写入、提交和推送权限；导入后先显示变更预览，再让管理员选择是否启动本地预览及发布。
2. 构建索引统一解析文章元数据、双链和系列信息；页面组件只消费生成的结构化数据。
3. 通过 VitePress 主题组件展示阅读时长、更新时间、变更记录、反向链接、相关文章和系列导航。
4. 读者服务采用 GoatCounter（匿名访问统计）与 Giscus（基于 GitHub Discussions 的评论）；仅在显式配置后加载。

## 内容模型

除已有 `title`、`category`、`tags`、`date`、`description`、`difficulty`、`draft` 外，公开文章可选使用：

```yaml
updated: 2026-08-12
featured: true
series: LangGraph 入门课
seriesOrder: 2
changeLog:
  - date: 2026-08-12
    summary: 增加环境变量排错说明
```

正文可用 `[[目标文章标题]]` 或 `[[目标文章标题|显示文本]]` 创建知识双链。标题必须唯一；解析成功后输出标准站内链接。公开文章不得链接到草稿。

## 发布体验

导入器在写入前建立 import plan，其中包括目标 Markdown 路径、复制图片列表、重写图片链接、元数据和将要修改的文件。写入后输出：目标目录、识别的标签、图片数量及新建/修改文件摘要。

默认动作变为：写入本地文件后询问是否启动本地预览；预览退出后才询问是否提交，提交后才询问是否推送。保留“只导入”的退出路径。命令失败或用户拒绝时，已写入的内容不丢失，Git 操作不执行。

## 知识网络与课程路径

索引将为每篇公开文章保存：出站双链、反向链接、按共享标签计算的相关文章、所属系列及前后文章。相关文章按共享标签数降序，再按更新时间和标题稳定排序；最多显示三篇，不包含自身、草稿和同系列的相邻文章。

`series` 相同的文章按 `seriesOrder` 升序组成课程路径。每篇文章显示系列名称、进度、上一篇和下一篇；新建的课程页列出全部公开系列。相同系列内的 `seriesOrder` 必须唯一。

## 内容运营

文章页展示创建日期、可选更新时间、由正文中文/英文词数估算的阅读时长、可选变更记录和可选精选标记。首页及更新页优先展示精选内容，随后按 `updated`（缺省为 `date`）倒序展示。RSS 与 Sitemap 使用更新时间，且始终过滤草稿。

## 读者增长与隐私

新增一个站点公开配置模块：

```ts
export const engagement = {
  goatCounterCode: '',
  giscus: {
    repo: '',
    repoId: '',
    category: '',
    categoryId: ''
  }
}
```

空值代表关闭。管理员先在 GoatCounter 创建站点、在 GitHub Discussions 中安装 Giscus，再把服务提供的公开标识填入配置。站点页脚提供 RSS 订阅与反馈/评论入口；不实现邮件订阅表单。

## 验收标准

1. 导入命令在未执行 Git 操作前输出完整预览摘要，并默认提供本地预览选择。
2. 合法双链被转换为站内链接，页面展示反向链接和最多三篇相关文章；错误双链、歧义标题和指向草稿的双链均被内容检查拒绝。
3. 系列页、文章相邻导航、阅读时长、更新时间、精选与变更记录正确渲染；系列序号重复被拒绝。
4. 草稿不出现在所有生成列表、课程页、关联内容、RSS 与 Sitemap。
5. 关闭 engagement 配置时没有第三方脚本；填入有效公开配置时，文章页加载 Giscus、全站加载 GoatCounter。
6. 新增单元测试覆盖索引、导入预览、内容校验、生成数据和主题页面；现有测试、内容检查与生产构建通过。
